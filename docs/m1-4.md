# M1.4 configuration editor

Install the optional Qt Widgets dependencies in the Fedora Toolbox environment
where you run DINAD.

```sh
python -m pip install -e '.[gui]'
python -m dinad gui --project examples/first_environment/project.toml \
  --profile examples/first_environment/controls.toml
```

The default backend is silent. For audio, run a dedicated loopback TCP
SuperCollider server as described in [M1.3](m1-3.md), then append
`--backend supercollider --exclusive-server` to the GUI command. Use `--port`,
`--sample-rate`, `--sclang` and `--library` as needed for that installation.
A DINAD module file supplied with `--modules` can also select the live provider.

- **Ctrl+Space** starts or stops the loop. Tab to anchor, tempo or seed and
  press Enter to apply a semantic edit. With focus on the performance
  panel, press a bound profile key directly. The example binds **+** and
  **−** to anchor and **F** and **S** to tempo. Text fields and the F12
  editor keep normal typing behavior. The **Profile key** field also accepts
  tokens that cannot be used as unambiguous shortcuts.
- **F12** opens the TOML editor inside the performance window and returns
  focus to the performance panel when it closes. Choose among the project,
  profile and module files supplied at launch.
- **Ctrl+S** validates and applies the editor buffer. Syntax diagnostics
  point to the TOML parser's line and column. Schema diagnostics identify
  the affected key when it can be located unambiguously.
- **Reload** reads the file from disk. Ctrl+S then applies the reloaded
  content. Reloading, switching documents or closing prompts before
  discarding unsaved text.

Project edits affect the next unscheduled onset and preserve the transport
clock, active note gates and take. Profile edits change subsequent key input.
Applying a changed project or profile starts a fresh semantic undo history.
Provider or live constructor setting changes require stopping playback
before saving. The next start uses the rebuilt transport. Other module file
edits are validated using the existing DINAD schema.

The file worker stages and validates text. The transport thread checks the
candidate against the current runtime, checks for external file changes,
atomically replaces the file, and publishes the prepared settings. Invalid
text, runtime validation errors, stale files and failed file replacement
leave the running settings untouched. The Qt event loop runs separately
from transport scheduling and audio I/O.

After merging M1.4, run the owner-led 30–60 minute Fedora listening and
usability check in the [M1 plan](m1.md) before starting M1.5. Include repeated
editor use during sustained playback, keyboard navigation, invalid-edit
rollback, and PipeWire CPU and underrun checks. Automated results cover
the available anchor, tempo and seed controls. Density and native synthesis
parameter controls remain unavailable in the current built-in composition.
