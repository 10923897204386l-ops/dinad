# M1.5 headless MDA ePiano

DINAD hosts the **MDA ePiano** from Fedora's `lv2-mdala-plugins` package.
The verified URI is `http://drobilla.net/plugins/mda/EPiano` at LV2
version 2.0, tested with Fedora 43 package `1.2.10-9.fc43`. The separate
`lv2-mdaEPiano` package exposes the older Event port and is incompatible
with this adapter.

Jalv provides a headless JACK host and is a useful alternative for
exploring LV2 port connectivity. M1.5 uses a small Lilv helper for the
single verified instrument so DINAD can drive one event schedule through
both JACK playback and offline rendering. The helper discovers and checks
the URI, version, required features, Atom MIDI input, stereo output,
and all twelve control symbols and ranges before instantiation. The
DINAD `modules` command lists the verified adapter contract.

## Fedora Toolbox setup

```sh
sudo dnf install gcc make pkgconf-pkg-config lilv-devel lv2-devel \
  pipewire-jack-audio-connection-kit-devel libsndfile-devel lv2-mdala-plugins
make -C tools/lv2
export PATH="$PWD/tools/lv2:$PATH"
python -m pip install -e '.[gui]'
python -m dinad validate-modules examples/first_environment/epiano.toml
```

Use `LV2_PATH` if the Fedora bundle lives outside the standard search
locations. A DINAD TOML `helper` setting can specify the path to the
compiled helper instead of adding it to PATH. Live sample rate must
match the PipeWire JACK graph.

```sh
python -m dinad gui --project examples/first_environment/project.toml \
  --profile examples/first_environment/controls.toml \
  --modules examples/first_environment/epiano.toml
```

Start playback with Ctrl+Space. Connect **DINAD-EPiano:left** and
**DINAD-EPiano:right** to the intended stereo sink in the PipeWire graph.
The helper leaves routing to the user and preserves the default device.
Its ports exist while playback is active. The example maps DINAD anchor
to hardness and treble boost with explicit scales. Anchor controls change
the notes and both timbre parameters at the next unscheduled onset.

The JACK callback runs native code and consumes a bounded event queue.
MIDI uses frame offsets within each LV2 Atom Sequence. The helper splits
processing at control changes, so the new port value reaches the plugin
at the specified frame. The plugin determines when that control affects
its synthesis. DINAD's live clock still maps host monotonic deadlines
to the JACK cycle. All DINAD parts use the same ePiano instance. MIDI uses integer pitches and a fixed velocity.
Overlapping gates of the same pitch release only after the final gate.
The host releases notes on stop and allows a half-second release window.

## Recall and offline rendering

The module TOML stores constructor control values, editable through F12
while the transport is stopped. During performance, semantic controls
can change mapped parameters. A saved take records initial control values,
timestamped automation, and the helper's late-event and xrun counters.

```sh
python -m dinad live --modules examples/first_environment/epiano.toml
# Enter start, make edits, enter stop, then save take.json and quit.
python -m dinad render take.json epiano.wav \
  --modules examples/first_environment/epiano.toml --restore-module-state
```

Restore checks the schema, module version, parameter bounds and event
order. The render uses the saved note history, controls and automation
with the selected render rate and tail. A normal render uses the TOML
constructor settings. Live configuration or binding edits require a
stop and restart. Opaque plugin state, vendor presets, pitch bend,
multiple simultaneous plugins, and staged `play` through ePiano are
outside this adapter's supported operations.

## Verification

Automated Fedora checks cover discovered metadata, actual offline MIDI
onset at sample 123, recall of control values and automation, and a live
PipeWire stereo capture with mapped anchor changes and a restored render.
The final short runs at requested 256- and 512-frame latency each logged
zero late events, zero playback xruns, and one startup xrun.
This establishes operation on the tested bundle and host configuration.
Run the short owner listening check for sound, mapping response, and
save/restore before proceeding to M1.6.
