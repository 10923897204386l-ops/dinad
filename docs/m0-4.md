# M0.4: provisional SuperCollider backend

DINAD now compiles resolved event histories for SuperCollider. Python schedules
musical intent; native SuperCollider SynthDefs own voices, envelopes, delay and
reverb. No sound device is needed for offline rendering. The Python tests run
without SuperCollider; a separate optional integration test exercises real tools.

## Generate and render

Install SuperCollider language and server tools (`sclang`, `scsynth`) using your
platform's package manager, then install DINAD normally. A Qt-capable sclang
installation may need `QT_QPA_PLATFORM=offscreen` on a headless host.

```sh
mkdir -p renders
python -m dinad demo --project examples/first_environment/project.toml > renders/demo.json
QT_QPA_PLATFORM=offscreen python -m dinad render renders/demo.json renders/demo.wav
```

The output must be a new `.wav` file; existing audio is not overwritten. The
parent directory must exist. Output is stereo float32 WAV, default 48 kHz. Flags:

```text
--sample-rate 48000    integer 8000–192000
--tail 2              effect tail in seconds, 0.5–60
--timeout 60          per-process deadline, positive seconds
--sclang PATH         language executable (default: search PATH)
--scsynth PATH        server executable (default: search PATH)
--library PATH        optional sclang class-library YAML
--plugins PATH        optional native server plugin directory
```

No hidden fallback to a mock render occurs. Unsupported instrument IDs, invalid
pitches/times or settings fail before executing SuperCollider. Only `drone`,
`pad`, `arp.slow` and `arp.fast` are currently mapped. These use packaged native
SynthDefs; arbitrary instrument loading and third-party plugin hosting are not
implemented. Frequencies must be positive and below sample-rate Nyquist. Score
positions must be below 2**31 seconds and preserve a positive voice lifetime.

An adjacent `dinad-render-*` directory retains the generated script, OSC score,
version/compiler/server logs, rendered file and manifest. The CLI prints the
manifest as JSON, including event and SynthDef hashes, engine versions, requested
settings and actual WAV duration, peak and RMS. On subprocess timeout/failure,
logs remain available; no completed output is published. WAV format, sample rate,
channels, duration, finite samples, signal presence and full-scale limits are
validated before publishing the output. Empty event histories may render silence.
Wave inspection requires no ffmpeg dependency. Install assets are included in
the wheel, so rendering works outside the source checkout.

## Musical timing and routing

Node group 1000 owns a run; effects node 1001 reads private stereo bus 16 and
writes bus 0/1. Voices 1002 onward are inserted before the effects node. Drone
uses a sine oscillator, pad uses detuned filtered VarSaw, and both arpeggio clocks
use a sine voice. Conservative fixed gains feed native delay/reverb with a
LeakDC/tanh output stage; this is not a production mixer or mastering chain.

At the resolved note onset, a voice starts. At onset + duration, its gate is
released; its native envelope then frees it (release: drone 0.3 s, pad 0.4 s,
arp 0.08 s). At equal timestamps, releases precede new starts, preserving stable
history order within each kind. The group is freed at the last gate release plus
the chosen effect tail. The tail is a finite render policy, not complete DSP
state capture, and can truncate remaining reverb.

Score compilation pins a one-second clock so user musical-tempo defaults cannot
rescale resolved timestamps. The offline score first loads SynthDefs, waits 0.1 s before setting up the group
and return, and starts musical time zero after another 0.1 s. This fixed 0.2 s
transport offset is explicit in the manifest. A 16-beat demo at 120 BPM with the
default 2 s tail renders about 10.2 s; SC block rounding can add a block.

## Provisional live submission

Start a dedicated SuperCollider server yourself, then run:

```sh
QT_QPA_PLATFORM=offscreen python -m dinad play renders/demo.json renders/live-logs \
  --exclusive-server --host 127.0.0.1 --port 57110 --sample-rate 48000
```

The log directory must be new. `--exclusive-server` explicitly declares that
DINAD owns node group 1000 and stereo bus 16 for this run. Do not use this path
with an unrelated composition/server sharing those resources. The adapter does
not implicitly start audio hardware, reserve buses dynamically or negotiate
server configuration. The expected sample rate must match the server's nominal
rate; a mismatch fails before notes are scheduled. UDP host/port are explicit.

The adapter queries server status, enables node notifications, synchronizes
SynthDef loading, and sends timestamped bundles from a fixed future origin
(default `--lookahead 0.2`, allowed 0.05–5 s). All commands at an equal timestamp
share one ordered OSC bundle; this avoids races between group and voice setup.
`/fail` replies abort the run. Every expected voice must report both start and
end before success is reported. The final group cleanup is synchronized.

This adapter submits the full short schedule ahead of time, not rolling updates.
There is no audio-clock calibration or live parameter injection yet. A missing
server/response is bounded by `--timeout` (which must exceed the whole run).
On failure it attempts to free only DINAD's reserved group via UDP; cleanup is
best effort if the server is unreachable. Network timetag accuracy, late-packet
handling and hardware timing require further validation. A successful live run
means the server accepted voices and reported their lifecycle, not that anyone
heard them.

## Tests and cloud validation

```sh
python -m pytest
# Run the optional real NRT test when tools are installed:
DINAD_TEST_SCLANG=/usr/bin/sclang DINAD_TEST_SCSYNTH=/usr/bin/scsynth \
  QT_QPA_PLATFORM=offscreen python -m pytest tests/test_supercollider.py
```

Optional integration-test settings `DINAD_TEST_LIBRARY` and `DINAD_TEST_PLUGINS`
support an extracted temporary install. Logs and generated media belong outside
Git. Source tests cover score lifetimes/order, unknown instruments, process errors
and timeouts, output validation, atomic publication safeguards and live cleanup.

The cloud workspace used extracted Debian SuperCollider 3.13.0 language/server
packages and dependencies under `work/sc-temp/`, with no system installation.
A local library YAML and Qt resource configuration enable headless use. Actual
NRT output was independently inspected using ffprobe and ffmpeg as well.

Retained failures during setup/build:

- Initial extracted executables could not find `libscsynth.so.1`; adding both
  extracted library directories fixed lookup.
- Headless language startup initially aborted for a missing QtWebEngineProcess,
  then failed for unresolved Qt resources. Explicit local Qt paths/config fixed
  both attempts. Failure logs remain outside Git.
- The first live dummy-server run exposed a real race: separate equal-time OSC
  bundles could create an effects node before its group. The CLI falsely reported
  success because server failures were not monitored. The failure is retained;
  ordered grouped bundles and fatal `/fail` handling fix both defects, with
  regression tests. Voice lifecycle confirmation was subsequently added.
- Hardware audio remains unavailable. JACK dummy testing is silent, and memory
  locking/real-time priority warnings occur in this container. No audio was
  auditioned and no real-time latency or listening quality is claimed.

## Fedora handoff

Use a Toolbox container rather than altering Kinoite's immutable host. Verify
the available SuperCollider and PipeWire/JACK packages with `dnf info` before
installing. Ensure the Toolbox can access the user PipeWire/JACK session. First
run the same offline render and inspect the manifest; then play the WAV locally
at a conservative volume. For live tests, start an exclusive SC server against
PipeWire/JACK, confirm its actual sample rate and output connections, and pass
that expected rate to `dinad play`. Record engine versions, sample rate, buffer,
routing, dropouts and measured latency. Validate drone release, pad transitions,
arpeggio clocks and delay/reverb tails by listening. These are M0.5 checks.

Final build smoke results on Python 3.12.14 / SuperCollider 3.13.0:

- PASS: 138 tests with the real NRT test enabled, in the checkout and against a
  fresh wheel from outside it. Without engine tools, 137 pass and the optional
  NRT test is skipped.
- PASS: installed CLI renders all 61 events into a 48 kHz stereo float32 WAV,
  10.201333 s long, with finite samples, peak 0.139662 and RMS 0.036196.
- PASS: independent ffprobe/ffmpeg inspection, packaged assets, Unicode/space
  paths, no-clobber output behavior and M0.3 configuration validation.
- PASS: two consecutive installed-CLI live runs on the same isolated JACK dummy
  server; every run confirms 61 voice starts and 61 ends, with no server node
  failures. Notification registration is removed at completion. Both test server
  processes were stopped afterward. This is silent and non-real-time dummy I/O.
- RETAINED FAIL: the startup/resource failures and the initial live race/false
  success described above. Corrected runs pass. Hardware listening, device
  latency and Python 3.11 remain untested.

Full build diagnostics remain under `work/sc-temp/`, including
`final-smoke-results.json`, `live-installed-results.json`,
`final-source-tests.log` and `live-failure-1.json`. No system packages were changed;
the extracted tools remain temporary and user-local for continued validation.
