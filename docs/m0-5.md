# M0.5 — Fedora Toolbox audio validation

M0.5 provides local setup, a read-only diagnostic collector and a repeatable
render/playback checklist. It adds no audio engine or Python runtime dependency.
The SuperCollider render/play commands require M0.4, integrated through PR #4
as `48a71341598392e12d1ff90ac09ccd7b9768ba13`; the diagnostics can run
independently. Use current authoritative main for the audio steps.

## Toolbox setup

On Kinoite, enter your development Toolbox. Install inside the container, leaving
the immutable host unchanged. Check available packages before installation:

```sh
toolbox enter
dnf info supercollider pipewire-utils pipewire-jack-audio-connection-kit pulseaudio-utils
sudo dnf install supercollider pipewire-utils pipewire-jack-audio-connection-kit pulseaudio-utils
```

Use Python 3.11+ and a project virtual environment with the reviewed M0.4 build.
Activate it and verify commands before testing:

```sh
source .venv/bin/activate
python -m dinad --help
sclang -v
scsynth -v
pactl info
pw-link -i
pw-link -o
```

The Toolbox needs the logged-in user's PipeWire session. Successful `pactl info`
should identify the host session; `pw-link` should expose the intended physical
output. A missing `/dev/snd` inside Toolbox does not by itself prevent session
PipeWire/JACK access. If sudo is blocked by a Codex sandbox, run the installation
in your own Toolbox terminal; do not change host packages or weaken the sandbox.

## Capture diagnostics

Run from this checkout; collector scripts are repository tools, not installed
Python entry points. Store reports locally outside version control:

```sh
mkdir -p local/m0-5
python scripts/fedora_audio_check.py --output local/m0-5/before.json
```

The script uses only the standard library, starts no audio, records no microphone
and changes no settings. It records executable versions, server details, devices,
links, clock metadata and the PipeWire graph. Exit 0 means tools/session responded,
not that sound or latency passed; exit 1 means missing/failed/timed-out probes.
Exit 2 covers invalid arguments/output errors. Output files must be new; each
probe has a five-second deadline. Reports can contain device names and local
paths; review before sharing. Missing diagnostics must never turn into a silent
mock-audio fallback.

## Render and hear the example

In the activated M0.4 environment, use a new run directory:

```sh
mkdir local/m0-5/run-1
python -m dinad demo --project examples/first_environment/project.toml > local/m0-5/run-1/demo.json
QT_QPA_PLATFORM=offscreen python -m dinad render local/m0-5/run-1/demo.json local/m0-5/run-1/demo.wav > local/m0-5/run-1/render.json
pw-play --volume=1.0 local/m0-5/run-1/demo.wav
```

Check the render manifest: 61 events, stereo float WAV, 48 kHz, about 10.2013 s,
finite nonzero signal, peak below 1. Default-seed reference peak is about 0.13966
and RMS 0.03620; cross-platform audio is not promised bit-identical. Render refuses
existing outputs. Use the M0.4 --sclang/--scsynth/--library/--plugins options for a
nonstandard installation. Offscreen Qt avoids requiring a GUI display.

`pw-play --volume=1.0` is unity stream gain, 6.02 dB louder than 0.5. Set a
comfortable system volume yourself; do not normalize reports by silently
changing master or microphone levels. Listen for the sustained drone, pad chord
changes, both arpeggio clocks, release envelopes and fading delay/reverb. Record
what the listener actually confirms; process exit status does not establish sound.

## Live server and explicit routing

Start an exclusive server in a dedicated terminal/shell. Use an unused port and
retain the PID; never attach DINAD to an unrelated composition. This example has
no audio inputs and changes no global PipeWire clock policy:

```sh
PIPEWIRE_LATENCY=256/48000 pw-jack scsynth -u 57120 -B 127.0.0.1 -i 0 -o 2 -z 64 -Z 256 -S 48000 -R 0 > local/m0-5/run-1/server.log 2>&1 &
sc_pid=$!
```

Wait for “SuperCollider 3 server ready” in the log. Verify the actual rate and
buffer reported there; a request is not proof of negotiation. In another
terminal inspect `pw-link -o` and `pw-link -i`. With the expected SuperCollider
client name and a default stereo FL/FR sink, connect:

```sh
sink=$(pactl get-default-sink)
pw-link 'SuperCollider:out_1' "$sink:playback_FL"
pw-link 'SuperCollider:out_2' "$sink:playback_FR"
pw-link -l > local/m0-5/run-1/routing.txt
QT_QPA_PLATFORM=offscreen python -m dinad play local/m0-5/run-1/demo.json local/m0-5/run-1/live-1 --exclusive-server --port 57120 --sample-rate 48000
QT_QPA_PLATFORM=offscreen python -m dinad play local/m0-5/run-1/demo.json local/m0-5/run-1/live-2 --exclusive-server --port 57120 --sample-rate 48000
```

Check names and links first; adapt names for other channel maps/devices. Existing
links need not be recreated. The expected sample rate must match actual server
rate. Each CLI log directory must be new. Success requires all 61 voice starts
and ends, no `/fail` replies and completed cleanup. Also confirm sound by listening.

Run `pw-top -b -n 30` during playback and retain its output. Compare error counters
before/after and distinguish existing counts or startup transitions from increases
during music. Record actual device/rate/quantum, CPU warnings and audible dropouts.
Repeat at another buffer only if needed; do not claim sustained-load reliability
from two short demos. Stop only the server you started, in its original shell:

```sh
kill -INT "$sc_pid"
wait "$sc_pid"
```

## Latency and acceptance record

A 256-frame buffer at 48 kHz is 5.33 ms per buffer, not full device latency.
An acoustic test can simultaneously record the output monitor and microphone,
then correlate repeated chirps; microphone use must be intentional. It includes
sound travel, input processing and graph alignment and excludes application work
before the monitor. Use an electrical loopback for calibrated round-trip latency.
Do not divide an acoustic result by two to claim output latency. DINAD's default
200 ms lookahead is a separate scheduling parameter, not measured hardware latency.

Keep a per-run record of source SHA, Python/engine versions, real or dummy I/O,
actual routing/rate/buffer, render metrics, lifecycle results, error-counter changes,
listener observations, latency method and unresolved limits. Keep generated WAVs,
JSON graphs, raw microphone recordings and machine-specific configuration outside
Git. A narrative validation summary may be committed; review identifying details.

See [local results](m0-local-audio.md): 138 M0.4 tests, four real-speaker live runs,
listener confirmation of clear/adequate playback, and a 12.9 ms acoustic estimate.
Calibrated wired latency, long-duration load testing and a permanent system install
remain outstanding. Timed live parameter injection/rolling audio-clock transport
is not implemented by M0.4 or M0.5; M0 acceptance on that point remains partial.
