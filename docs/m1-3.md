# M1.3 continuous live transport

The `live` command loops the 16-beat DINAD composition. By default it uses
the silent mock backend. Start the session, then enter `start` and issue
commands while the transport is running.

```sh
python -m dinad live --profile examples/first_environment/controls.toml
```

- `start` begins a new take at beat zero with the current project settings.
- `set composition.anchor 55`, `set transport.tempo_bpm 90`, and
  `set generation.seed 4` change the next unscheduled onset. Existing
  notes retain pitch and gate duration. Keyboard profile commands and
  `undo` use the same semantic control IDs.
- `stop` releases active notes. `save path.json` saves the stopped take
  as a schema-1 event history for normal replay and rendering. Each edit
  records its receipt time and effective onset. The current take lives
  in memory. Save it before starting a new take or replacing a playing project.
- `replace project.toml` validates the candidate first, releases the old
  voices, and restarts at beat zero if the transport was running.
- `quit`, end of input, and Ctrl-C close the session and release its notes.
  After a playback error, `start` retries with the current project.

## SuperCollider

Start a dedicated TCP-enabled scsynth with the project's audio routing.
For a local engine with the standard stereo output and no inputs:

```sh
scsynth -t 57110 -B 127.0.0.1 -i 0 -o 2 -S 48000 -R 0
python -m dinad live --backend supercollider --exclusive-server
```

The explicit exclusive-server flag reserves group 1000, effects node 1001,
and stereo bus 16. Use one DINAD transport per dedicated server. The live
adapter compiles the existing synth definitions with headless sclang and
sends timestamped OSC over one persistent local TCP connection. It orders
coincident releases before onsets and waits for server acknowledgements.
After a connection fault it attempts to free the reserved group over a new
connection. If the server is unreachable, cleanup cannot be confirmed.

Set `--port` and `--sample-rate` to match the server. Alternatively, use
`--modules config.toml` and select the live provider with:

```toml
schema_version = 1

[operations.live]
module = "dinad.supercollider"
version = "supercollider-v1"

[operations.live.settings]
sample_rate = 48000
```

The continuous path uses a 50 ms scheduling lead and a short release
window on stop. Beat deadlines use a host monotonic clock mapped to OSC
timetags. The server schedules the bundles, but DINAD does not measure
sample-clock drift or input-to-audio latency in this path. Controls
change generated notes and timing. Built-in native runtime parameter
writes, external plugins and concurrent providers are outside this increment.
