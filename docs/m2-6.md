# M2.6 Beat-based controller schedule

The existing `dinad perform TIMELINE OUTPUT` command now accepts a
version 1 timeline with `[[controller]]` entries.

```toml
schema_version = 1

[[controller]]
beat = 4
parameter = "composition.tension"
value = 2

[[controller]]
beat = 8
parameter = "transport.tempo_bpm"
value = 90
```

DINAD validates values through its semantic parameter registry. Beat
positions are relative to the start and must be ordered within the
16-beat performance. Entries on the same beat run in file order
before notes on that beat. A tempo change affects the wall-clock time
of subsequent beats. Takes retain ordered changes and resolved notes.

A timeline can use either the new beat-based controller entries or the
existing seconds-based actions. This first increment covers finite,
offline set operations. Live scheduling, ramps, Lua execution and
manual-input precedence are later work.
