# M1.4.1 — Keyboard and seed usability follow-up

Status: **approved for inclusion at the start of the upcoming M1.5 build**. This is a small scoped implementation task, not a claim that the changes are already built.

## Fedora M1.4 owner test
Owner reports that the M1.4 interface and editor work as planned, including manual seed editing. Two minor usability findings: F12 requires an Fn modifier on the laptop, and seed lacks a convenient keyboard control. Record M1.4 hands-on gate as **PASS with minor follow-ups**; no GUI redesign required.

## Required changes
1. **Editor toggle**: unmodified **backtick / grave accent** key (`), usually the key below Escape, toggles the in-window DINAD configuration editor when focus is on the performance panel. Keep F12 as an alternative. Respect keyboard layouts and Qt key events; do not intercept ordinary backtick typing inside the text editor, text entry, dialogs or command fields. Existing unsaved-change protection remains in force. Test focus/shortcut conflicts.
2. **Seed entry**: expose the current generative **random seed** in the performance panel and provide a keyboard-accessible numeric edit action (discoverable shortcut/help label). Use the existing validated DINAD semantic config/application model, not GUI-local RNG or a direct backend mutation. Seed bounds/type follow the existing schema.
3. **Seed semantics**: setting a seed while playing **does not silently restart** or retroactively change the current sequence. Clearly indicate whether it is staged for the next generation/restart, or can be applied safely at a defined musical boundary using the current engine's supported semantics. Do not invent hot-swap capabilities. A distinct explicit **new seed / regenerate** action may generate a new valid seed, but must require an explicit restart/transition command before it affects ongoing playback. Show active versus pending seed when different.
4. **Reproducibility**: same seed + same project/configuration + same engine/version should reproduce the same resolved musical event decisions under the same execution conditions. Test using event histories, not bit-identical audio.
5. Tests: Qt offscreen keyboard/focus tests for backtick/F12 and text entry; seed validation, pending/active semantics and deterministic replay; no regressions to headless tests or audio lifecycle.
