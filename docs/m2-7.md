# M2.7 Beat-based controller ramps

Add `end_beat`, `end_value` and `steps` to a beat-based controller
entry to schedule linear interpolation through DINAD's semantic registry.

```toml
schema_version = 1
[[controller]]
beat = 0
parameter = "transport.tempo_bpm"
value = 120
end_beat = 8
end_value = 60
steps = 8
```

The example sets 120 BPM on beat 0 and schedules eight further values
through beat 8. Each value holds until the next update. Ramps support
continuous controls and 1 to 256 intervals, with a total cap of 4096
resolved operations per timeline. Updates merge by beat, with file
order breaking ties. A later ramp update can overwrite a set or another
ramp on the same parameter. Saved takes retain the resolved actions
and notes. This uses the finite offline performance path.
