# M0 — exploratory demo brief

Goal: demonstrate the architecture rather than build a full DAW.

## Minimum experiment
1. Generic object model with four-element anchor-relative harmonic structure, explicit motif and timing.
2. Reuse the harmonic object to control a pad's chord roots and an arpeggiator's home pitch.
3. Deterministic and seeded generative transformations with repeatable event streams.
4. Human-readable example project and control profile; keyboard-driven parameter changes.
5. Headless mock backend that emits timestamped events; tests compare reproducible output.
6. Provisional SuperCollider backend for Fedora: drone, pad and multi-clock cascade, simple delay/reverb, short audio render.
7. Log actual backend settings, timing, event history and limitations.

## Acceptance
- `python -m pytest` passes without audio devices or SuperCollider.
- A documented CLI can generate and compare identical mock event streams with fixed inputs/seed.
- Editing the anchor transposes dependent pad and arpeggiator relationships consistently.
- Live control actions can be captured as resolved events and replayed.
- Fedora listening/rendering procedure is documented; do not claim successful audio testing until performed.

## Boundaries
Do not build full GUI, plugin host, Csound integration, mastering suite, or comprehensive snapshot system in M0. Use small PRs: object model -> scheduler/mock -> control/config -> SuperCollider adapter -> local audio validation.
