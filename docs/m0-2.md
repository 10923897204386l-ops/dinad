# M0.2: deterministic mock composition

Install with `python -m pip install -e '.[dev]'`, then from the repository:

```sh
mkdir -p renders
python -m dinad demo --seed 42 --anchor 48 --tempo 120 > renders/first.json
python -m dinad demo --seed 42 --anchor 48 --tempo 120 > renders/second.json
cmp renders/first.json renders/second.json
python -m dinad replay renders/first.json
python -m pytest
```

The CLI writes JSON to stdout. Replay validates and submits resolved notes to a
fresh mock backend; it prints a count and does not regenerate the composition.
Generated histories belong in ignored `renders/`, not Git. Invalid files,
unsupported schemas and invalid musical values produce a concise CLI error.

The 16-beat demo emits 61 notes: one drone, four three-note pad chords, an
explicit slow arpeggio clock and a seeded fast clock. A single four-element
anchor-relative object supplies harmonic spans for both pad and arpeggios.
Changing `--anchor` shifts all parts equally. The clocks run at one beat and
half a beat, respectively; this is a small multi-clock demonstration, not yet
the cascading clock/trigger system envisaged for later audio experiments.

## Contracts

- `HarmonicContext` interprets an object instance into non-overlapping spans.
  Spans are half-open: at a boundary, the new harmony applies. Gaps raise a
  clear error. Sustained notes keep their onset pitch; no active-voice retuning
  or effect-tail analysis is implemented.
- `Part` contains resolved beat-domain `Note` values. `schedule` converts
  onsets and durations using a fixed positive BPM. The returned immutable
  `Event` tuple is ordered by seconds, with stable ties in part then note order.
- The backend protocol accepts complete note commands containing pitch,
  instrument ID, timestamp and duration. Each backend must ultimately own
  note termination. Separate note-off messages and voice IDs are deferred to
  adapter design; no real-time sleeping or Python audio callbacks are used.
- `MockBackend` records submitted events. `replay` validates history ordering
  before dispatch and forwards the stored values without pitch evaluation or RNG.
- JSON schema 1 records resolved events, seed, anchor, BPM, generator ID,
  DINAD/Python versions and mock backend version. No audio settings are claimed.
  The loader needs only the schema and resolved events to replay. Historical
  generation metadata is informational, not consulted during replay.
- `VariationState` owns a local seeded RNG. The fast arpeggiator consumes it;
  explicit parts and global random state remain unaffected. Fresh composition
  calls start fresh state. Regeneration is tested within the recorded Python
  version; replay of stored events is the cross-version reproducibility path.

## Scope and next step

This increment compiles a complete short schedule ahead of time. An audio-clock
transport, rolling lookahead, live control logging, tempo changes and backend
instrument definitions remain future work. M0.3 adds versioned project/control
configuration and semantic actions. M0.4 connects the scheduling contract to
SuperCollider and an actual audio timeline. No synthesis or audio playback is
implemented here, and mock success does not establish audible or real-time
performance. The frozen production requirements remain unchanged.

## Cloud validation report

Validation on Python 3.12.14:

- PASS: source tests, fresh non-editable wheel installation, dependency check,
  and tests against the installed package from outside the source checkout.
- PASS: independent CLI runs with seed 42 produced byte-identical JSON; replay
  submitted all 61 events successfully.
- PASS: invalid tempo and malformed JSON were rejected with exit code 2 and
  concise diagnostics. These are intentional negative checks, not build failures.
- FAIL (environment): a separate system WAV playback probe could not open an
  output device: `SDL_OpenAudio ... Couldn't open audio device` and
  `audio open failed`. This cloud workspace has no sound device. ffplay returned
  zero despite that error, so its exit code alone was not accepted as success.
- PASS: the same WAV passed through SDL's silent dummy output. This tests the
  system playback path only; DINAD has no synthesis backend yet.
- NOT TESTED: Python 3.11, SuperCollider, actual audible playback, audio-device
  timing and latency. These do not block the headless M0.2 mock milestone.

Full smoke commands and stdout/stderr are retained outside Git in the cloud
workspace under `work/m0-2-smoke-results.json`. No generated recordings or
machine-specific logs are committed.
